# TCP vs UDP Comparison

| Feature                | TCP (Transmission Control Protocol)                                               | UDP (User Datagram Protocol)                           | Underlying Mechanisms/Technologies                                                            |
| ---------------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| **Connection**         | Connection-oriented                                                               | Connectionless                                         | TCP: Three-way handshake (SYN, SYN-ACK, ACK)<br>UDP: No connection establishment              |
| **Reliability**        | Reliable - guarantees delivery of data                                            | Unreliable - no guarantee of delivery                  | TCP: Sequence numbers, checksums, ACKs<br>UDP: Only basic checksums                           |
| **Ordering**           | Maintains order of data                                                           | No inherent order preservation                         | TCP: Sequence numbers for reassembly<br>UDP: No sequence tracking                             |
| **Error Detection**    | Extensive error checking and correction                                           | Basic error checking, no correction                    | TCP: Checksums + retransmission protocol<br>UDP: Only simple checksum                         |
| **Flow Control**       | Yes - prevents sender from overwhelming receiver                                  | No flow control                                        | TCP: Sliding window protocol, buffer management<br>UDP: None                                  |
| **Congestion Control** | Yes - adapts to network congestion                                                | No congestion control                                  | TCP: Slow start, congestion avoidance, fast retransmit/recovery<br>UDP: None                  |
| **Speed**              | Slower due to overhead                                                            | Faster due to minimal overhead                         | TCP: Connection setup, larger headers, ACKs<br>UDP: Minimal headers, no connection overhead   |
| **Header Size**        | 20-60 bytes                                                                       | 8 bytes                                                | TCP: More fields for sequence, ACK, window size, options<br>UDP: Minimal header fields        |
| **Handshaking**        | Three-way handshake                                                               | No handshaking                                         | TCP: SYN → SYN-ACK → ACK sequence<br>UDP: None                                                |
| **Data Boundaries**    | Stream-based (byte stream)                                                        | Message-based (datagram)                               | TCP: Continuous byte stream with segments<br>UDP: Discrete messages with preserved boundaries |
| **Acknowledgment**     | Acknowledges received packets                                                     | No acknowledgment                                      | TCP: Cumulative/selective/delayed ACKs<br>UDP: None                                           |
| **Retransmission**     | Retransmits lost packets                                                          | No retransmission of lost packets                      | TCP: Timeout-based & fast retransmit<br>UDP: None (application must handle if needed)         |
| **Use Cases**          | Web browsing (HTTP/HTTPS), email (SMTP), file transfers (FTP), secure shell (SSH) | Video streaming, VoIP, DNS, online gaming, IoT devices | TCP: Applications requiring reliability<br>UDP: Applications requiring speed/low latency      |
